## Code architecture (slices.md)

- D1 | PR 3's keying needs the key on the processor (`villanelle({ key })`, called during expansion), so the key moves to `diff`'s call, as O4 directs | PR 3 at cb08803 calls the key rule inside `Expander.statement` | keep it on the processor
- D4 | addresses move with the key: `IDirective.address` is removed; `IRendered.addresses({ key })` is the one home of the address rule and `diff` uses it; each `Change` keeps its `address` | an address without its key would be a second, positional notion of identity | `render(graph, { key })` keeping `address` on directives (smaller change, but the key would sit on render, not diff's call)
- D5 | `KeyRule` takes the rendered `IDirective`; `IKeyInput` is removed | after render the whole directive exists; one shape instead of two; rasl's rule body (`d.name`, `d.parent?.name`, `d.args[1]?.text`) is unchanged | keep `IKeyInput`, built from each directive
- D6 | `diff` stays a processor method (`processor.diff(before, after, { key })`) and keeps PR 3's same-processor check | smallest change; diff redesign is out of scope | a free `diff` function without the check
- D7 | `IArgument.resolutions[0]` is the `$name` written on the value's own line, then toward where the value is written (the reverse of the variable steps in `origin.via`) | both owner-facing pages show `target $host`'s `[0]` as `$host` and `[1]` as `$leds_host`; design.md §7's "innermost first" read with PR 3's via order would give the opposite, so the examples win | via order (`[0]` = the step nearest the written value)
- D8 | S1 carries the mechanical move of every PR 3 caller and test to `render(await load(...))`, `IRendered`, the new graph and save; S2 keeps the rest of the PR 3 surface (key, `written` replacing `node`) | S1 changes `load`'s return type, so it is green alone only with its callers (skill §3.1, co-change §3.2); the brief put "all PR 3 callers moved" in S2 | S1 not green, or an old `load` kept beside the new one (a dual path)
- D9 | S1 writes every shared case of `conformance/written/`, S2's features included, gated by `needs` | S2 (ts/) and S3 (py/) run at the same time with disjoint paths, so neither may write `conformance/`; the load format already gates by `needs` | each slice writing its own cases (not disjoint)
- D10 | a written-layer case may name a fixture directory (`"fixture": "rasl/split"`) instead of inline files | one copy of the split fixture (rule of two) | copy its text into cases.json
- D11 | `IRendered.diagnostics` keeps PR 3's content and order (every code); `graph.diagnostics()` is the syntax diagnostics plus what the binding found, except render's codes (E4xxx, E5001, E5003, E5004, E5008) | load conformance stays byte for byte; design.md §5's split of codes is kept for the graph | render reporting only its own codes (would break every expected file)
- D12 | the only stored state besides texts is a read ledger: per (parent, spec) the paths or the rejection, per path the document or the rejection; a rejection is kept and `read(graph)` does not retry it | design rule 1 ("which files were read"); one read per file per graph (R21) | retry failures on each `read`
- D13 | a slice or index bound is a written value (`IWord` or `IReference`), so a `$n` in a bound is a reference the binding resolves and `reaches()` lists | PR 3 lets a bound be a variable (rule 4); a hidden reference would make rename and kind (3) miss it | bounds as plain text
- D14 | inserted statements: siblings' indentation; an empty block gets the parent's indentation plus the document's unit (its first indented line's leading whitespace, else four spaces); line breaks are the document's first | keeps the file's own style without a formatter | always four spaces
- D15 | a statement owns the comment lines directly above it (no blank line between) and a comment after its last token on its line | LibCST leading lines, Roslyn trivia (design rule 2) | own only the trailing comment
- D16 | a values text that is more than values (a `;`, a block) is BadTextError with one E2001 at the first such token; syntax errors keep their own codes | E2001 is the existing "token not allowed here" code; no new code | a new E2xxx code
- D17 | `rename` refuses a name that would change the statement's kind (`set`, `snippet`, `use`, an extension's), E2001 at 0:0 | a handle's kind never changes under it | allow it and detach the handle
- D18 | `createFsWriter`/`fs_writer` refuse a lost update (disk differs from `source`) writing nothing, then stage to temporary files and rename; the fetch writer sends one request per file and is not all-or-nothing | design.md hands the writer `source` for exactly this check; staging is design.md's "stage, then commit together" | write in place without checks
- D19 | `save` with nothing changed does not call the writer and returns `[]` | "saving twice writes once" (design.md §1) | call it with an empty batch
- D20 | a detached handle throws DetachedError from every member except `kind` | reading stale text silently is the hazard the error exists for | properties keep their last values
- D21 | directory names stay (`ts/src/load/` holds the middle layer); the low level is new `ts/src/written/` and `py/src/villanelle/written/` | renaming `load/` would mislabel its shared modules (source, origin, report) and add churn | rename `load/` to `render/`
- D22 | the new low-level reference takes `docs/low-level-api.md` (the owner's term for this layer); PR 3's page moves to `docs/rendered-tree.md` | his words name this layer "the low-level API" | a new page name for the low level
- D23 | the binding builds PR 3's `Argument` (rendered value) for include values and for render, so `ts/src/written/bind.ts` imports `load/tree.ts`'s class | an include's specs need expanded values (the `IExtension` contract), and value expansion needs one home (design rule 3) | inject a value builder into the binding; move `Argument` down a layer
- D24 | `graph.diagnostics()` returns located diagnostics (`ILocatedDiagnostic`, with file and steps), not span-only `IDiagnostic` as the sketch wrote | they span several files | the sketch's type
- D25 | `ReadError` extends `DiagnosticError` (E3004 at the root path, as before) | callers catching `DiagnosticError` keep working with the same diagnostic | a separate error class
- D26 | `IProcessor.read` lands in S2; S1 implements the read loop that `load` uses | the brief puts `read(graph)` in S2; `load` needs the loop anyway | expose it in S1
- D27 | `render`, `read` and `diff` refuse a graph or render another processor made (TypeError; ValueError in Python) | the graph's extensions are the processor's | accept any graph
- D28 | a handed-in value has one `IVariable` per name for the graph's life (removing and re-adding keeps it) | handle identity (`===`) for every written or handed thing | a new object per `setHanded`
- D29 | `variables()` order: documents in order, `$name`s in text order, then handed-in values in insertion order | stable, both languages, matches the briefing's table | sorted by name
- D30 | `IValueBase.remove()` throws BadTextError (E5009) when it would leave a `set` without a value | design rule 2 forbids leaving a text-alone rule broken | let it break and report it
- D31 | a statement's `place` and `text` run from its first owned token (a comment above it) to its last (a trailing comment) | `text` is "exact, with the comments it owns" (design.md §5), so `place` spans the same tokens | `place` at the name only
